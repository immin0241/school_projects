* Laravel로 구현한 인터넷 강의 청취 시스템입니다.
* 디자인은 인프런(https://www.inflearn.com/)의 디자인을 참조하였습니다.
* 이 프로젝트는 사용자와 교수자로 나뉘어 교수자는 강의 업로드와 강의실 관리를, 사용자는 강의 구독과 강의 청취를 할 수 있습니다.

## 2026 코드 리뷰 및 개선 (review/2026-access-control)

2024년 수업 프로젝트를 인턴십(멀티테넌트 SaaS 전환) 이후의 기준으로 다시 검토했습니다.
핵심은 **"역할(누구인가)"만 확인하고 "소유(누구의 것인가)"는 확인하지 않던 권한 설계**였습니다.

### 방법
고치기 전에 접근 제어 기능 테스트 18개(`tests/Feature/AccessControlTest.php`)를 먼저 작성해 기존 코드에서 돌렸고,
**18개 중 15개가 실패**했습니다. 수정 후 전체 테스트 26개가 통과합니다.

```bash
composer install && cp .env.example .env && php artisan key:generate
php artisan test
```

### 발견한 문제와 수정
| 구분 | 문제 | 수정 |
|---|---|---|
| 소유권 | 교수자이기만 하면 다른 교수의 강의실을 수정하고 영상을 올릴 수 있었음 (업로드 폼의 hidden `lecture_room_id`를 신뢰) | `LectureRoomPolicy`로 강의실 소유자인지 서버에서 확인 |
| 소유권 | 로그인한 사용자 누구나 다른 사람의 강의평을 삭제할 수 있었음 | `ReviewPolicy`로 작성자만 삭제 |
| 역할 | 강의 개설 라우트가 교수자 미들웨어 밖에 있어 수강생도 강의를 개설할 수 있었음 | 교수자 전용 라우트 그룹으로 이동 |
| 파일 접근 | `local` 디스크가 `public`과 같은 경로를 가리켜, 영상이 `/storage/...` 주소로 구독 없이 열릴 수 있었음 | 비공개 경로(`storage/app/private`)에 저장하고 권한 확인 후에만 제공 |
| 출력 | 강의 설명을 `<script>` 안에 이스케이프 없이 출력해 스크립트 삽입(XSS)이 가능했음 | `Js::from()`으로 JSON 인코딩해 전달 |
| 서버 검증 | "구독자만, 한 번만, 별점 1~5" 규칙이 화면에서만 지켜졌음 | 서버 검증과 정책으로 이동 |
| HTTP | 구독·구독 취소가 GET 요청이라 링크만으로 상태가 바뀜 | POST/DELETE + CSRF 토큰 |
| 기능 | 강의실 삭제 라우트가 존재하지 않는 메서드를 가리켜 삭제가 동작하지 않았음 | 메서드 연결 및 소유권 확인 |
| 안정성 | 강의가 하나도 없으면 메인 페이지가 500 오류 | 빈 상태 화면 처리 |
| 정리 | 테이블이 없는 `Video` 모델, 미완성 `get_lists`, 실제 앱과 맞지 않는 Breeze 기본 테스트(이메일 로그인 가정) | 제거하거나 아이디 로그인 기준으로 재작성 |

### 남은 과제
- 기존에 `public` 경로로 저장된 영상 파일은 `storage/app/private/videos`로 옮겨야 합니다.
- 교수자 대시보드의 집계 쿼리를 한 번의 쿼리로 줄이는 작업은 하지 않았습니다.
